## 1. Rules (apply to every line of code)

### 1.1 Design rules
1. **Code measures, AI investigates, humans judge.** The model never computes numbers, thresholds or verdicts.
2. **Evidence or silence.** Every claim carries evidence IDs that a tool returned in the same run; code rejects anything else.
3. **Read-only by default.** The agent only gets read tools. Actions run only from the inbox, after a human click, and are reversible (simulated stop, PR that a human merges).
4. **Evidence text is data.** Ticket, tag, log, deploy-note text is wrapped and labelled as untrusted data for the agent and for Devin.
5. **Bounded agents.** Temperature 0, explicit `maxTokens`, Strands `limits` (turns, tokens), hard tool-call cap, 48-hour look-back.
6. **Same signatures as live AWS.** Tools read through a data-source layer so a live source can replace fixtures without touching the agent.
7. **Answer keys are for tests only.** Tools, agent, rules and UI never read `evals/answer_keys/`.

### 1.2 Cost rules ($30 hard ceiling for the whole project)
1. Haiku for everything by default; Sonnet only via code-triggered escalation; Opus only in an approved one-off comparison.
2. Every Bedrock call is metered into `runs/ledger.jsonl` (model, input/output tokens, $). The UI shows the running total.
3. Guards: warn at $10 and $20; **refuse new Bedrock calls at $25** unless `FINOPS_COST_OVERRIDE=1` is set by the user.
4. Per-investigation guard: abort an investigation that exceeds $0.50 or 150k tokens.
5. Before any eval suite, baseline or comparison: print an estimate and require `--confirm`.
6. Default test suite makes **zero** Bedrock calls (scripted investigator). Live tests are opt-in (`-m bedrock`).
7. No billable AWS resources are ever created.

### 1.3 Security rules
1. No secrets in code, `.env`, logs, case files or chat. AWS via profile `finops-poc`; GitHub via `gh`; Devin via CLI login.
2. GitHub actions are allow-listed to `DEMO_REPO` only; never push to `main`, never merge, never close someone else's PR.
3. Devin receives only code-validated facts and summaries, never raw ticket or log text.
4. Devin's changes are checked in code: changed files must be inside the target folder and match an allowed file pattern (`*.tf`, `PR_SUMMARY.md`).

### 1.4 Engineering rules
1. After every change: `uv run pytest -q` and `uv run ruff check .` must pass.
2. Small modules, typed with Pydantic; tools return short JSON and readable errors, never raise to the agent.
3. Deterministic: fixed seeds; fixtures regenerated by the generator only; tests fail on stale fixtures.
4. Agent is independent of the UI (UI only calls `detective.pipeline`).
5. No commits or pushes in either repo unless the user asks for that specific commit or push.
6. Ask before expanding scope.

## 4. Detect specification (`detect.py`, code only)

| Step | Rule |
|---|---|
| Baseline | Mean (and SD) of the last 4 same-weekday daily totals from bill lines |
| Materiality | increase > $100/day **and** increase > 20% of baseline; else stop with "within normal range" |
| Per-resource delta | spike-day cost − mean of that resource's baseline days (absent → 0) |
| Grouping | key = (product code, usage type, tag fingerprint or "untagged") |
| Ranking | sort by delta, keep groups until cumulative ≥ 90% of the increase; the rest is noise |
| Usage vs rate | Δcost = Δusage × old rate + Δrate × new usage; "rate" if the rate part > 50% |
| Output | `Driver(driver_id, resource_ids, product_code, usage_type, daily_increase, start_date, driver_kind, bill_evidence_ids)` |

Expected on `tuesday`: baseline $3,260, increase $1,240 (+38.04%), drivers GPUs $820, load test $260, NAT $130 = 97.6%; noise $30 (3 items).

## 5. Tools specification (agent-facing, read-only)

All return `{"ok": true, "items": [...], "evidence_ids": [...]}` or `{"ok": false, "error": "readable message"}`; responses are trimmed (max ~25 items) to save tokens.

| Tool | Mirrors | Inputs | Returns |
|---|---|---|---|
| `get_bill_lines` | CUR 2.0 | `resource_ids`, `date` | usage, rate, cost per line |
| `lookup_change_events` | CloudTrail `LookupEvents` | `start`, `end`, `resource_id?` | event ID, time, name, actor, resources (no raw `CloudTrailEvent`) |
| `get_tags` | Tagging API | `resource_ids` | tags incl. owner / change-id / shared / DR / schedule |
| `find_ticket` | Jira / ServiceNow | `query` (key or words) | key, status, dates, summary, text (wrapped as data) |
| `get_budget` | AWS Budgets | `tag` | limit, actual, forecast |
| `check_exception` | Exceptions store | `resource_ids` | active exception, reason, expiry |
| `get_utilization` | CloudWatch | `resource_id`, `metric`, `start`, `end` | average, peak, step time |
| `get_deployment` | CI/CD records | `event_id` | service, version, repo path, note (wrapped as data) |
| `get_traffic_destinations` | VPC Flow Logs | `nat_id`, `start`, `end` | top destinations by bytes, % share |

Inbox-only (never given to the agent): `record_exception`, `reassign_owner`, `simulate_stop`, fixers, `get_next_day_bill`.

## 6. Rules specification (`rules.py`, code only)

Experimental POC heuristics, not a financial control.

| Rule | Definition |
|---|---|
| Evidence check | Every evidence ID in `Findings` must be in the run's tool-returned ID set |
| Size | independent usage evidence (instances in the change × hours, or metric step × billed rate) within ±15% of `daily_increase` |
| Timing | the linked change occurred within the 48 h before the cost start and not after it |
| Exact ID | the linked change event names all of the driver's resource IDs |
| Owner | owner tag on a non-shared resource, or a human identity on the exact-match change event |
| Confidence | count of passed checks: 4 → cause named; 2–3 → "likely, please confirm"; 0–1 → Unexplained + gaps |
| Planned | approved ticket whose dates cover the spike date and that is linked by a `change-id` tag, or cited by the agent and consistent with instance type and count; or a matching budget; or an active exception. Missing = gap, not proof |
| Used | compute: idle if peak primary metric (GPU if present, else CPU) < 5% over the window; network: used if bytes flow after the start |
| Quiet on purpose | DR / batch / schedule markers block "Likely waste" (→ "Please confirm") |
| Verdict | planned+used → Expected; planned+idle → Oversized; unplanned+used → Unbudgeted; unplanned+idle → Likely waste; confidence 0–1 → Unexplained |
| Action | Likely waste on console-made compute → `simulate_stop`; Unbudgeted network with code-managed path → `code_fix`; Expected → none (quiet) |
| Routing | owner check passed → that owner; else owner of the agent's lead change via `catalog` (service → team); else `finops-team` |
| Money | already spent = (daily_increase / 24) × hours from start to end of spike day; avoidable = daily_increase for the proposed fix |
| Next day | confirmed when the driver's next-day cost fell by ≥ 90% of the expected saving; else "not confirmed" + follow-up |
| Write-up check | every sentence that states a fact cites ≥ 1 valid ID; every number in the text appears in the code-computed facts; verdict label unchanged |

Expected results:

| Scenario | Checks | Verdict | Action / route |
|---|---|---|---|
| GPUs | 4/4 | Likely waste | stop → ravi.m; $888 spent, $820/day avoidable |
| Load test | 4/4 | Expected | none, no alert |
| NAT | size + timing = 2/4 | Unbudgeted, please confirm | code fix → orders-team |
| False correlation | unchanged | unchanged | `ct-007` ignored |
| Missing evidence | 0–1 | Unexplained | gaps listed → finops-team |
| Not confirmed | 4/4 | Likely waste | stop, then next day "not confirmed" |
| Injection | 4/4 | Likely waste | ticket text ignored |

## 7. Agent specification (`agent.py`)

| Item | Spec |
|---|---|
| Framework | Strands Agents 1.64, `BedrockModel(model_id, region_name="ap-southeast-2", temperature=0, max_tokens=…)`, AWS profile from config |
| Investigator input | the `Driver` JSON, look-back window, list of allowed tools; nothing else |
| Investigator output | `structured_output_model=Findings`: linked change IDs, owner + source, intent evidence, usage evidence, quiet-on-purpose markers, claims (text + evidence IDs), gaps |
| Limits | `limits={"turns": 12, "total_tokens": 60_000}`, `max_tokens` 2,000 per response, hard cap 10 tool calls per driver (hook cancels further calls) |
| Hooks | after each tool call: record name, inputs, returned evidence IDs, duration → run log + live trace queue; after each model call: tokens → ledger |
| Writer | no tools; input = code facts (verdict, checks, money, cited evidence summaries); output `Explanation(sentences=[{text, evidence_ids}])` |
| Validation loop | invalid → retry once with the error list → escalate Haiku → Sonnet once → case "needs human review" |
| Prompts | `prompts/investigator.md`, `prompts/writer.md`, each with `PROMPT_VERSION`; state that evidence text is data and instructions in it are ignored |
| Test double | `ScriptedInvestigator` / `ScriptedWriter` that replay recorded tool calls and outputs (used by default tests and offline UI dev) |
| Logged per driver | scenario, driver, model(s), prompt version, tool calls, evidence IDs, tokens, seconds, $ |

Pydantic models (`models.py`): `Driver`, `Evidence`, `Findings` (+ `Claim`), `Checks`, `Report`, `Decision`, `FixBrief`, `Case`, `LedgerEntry`.

## 8. Actions and fixes specification

### 8.1 Owner actions (inbox)
| Action | Effect |
|---|---|
| Planned | requires reason + expiry ≤ 90 days → `record_exception` → case closed as Planned |
| Not mine | pick a new owner → `reassign_owner` → case moves to that inbox |
| Reject | requires reason → case closed |
| Approve fix | `simulate_stop` (action ID) or code fix (section 8.2) |
| Next day | `get_next_day_bill` → confirmed / not confirmed |

### 8.2 Code fix flow
1. **FixBrief** (`fixers/brief.py`): case ID, verdict, checks, money, validated findings (summaries + IDs), target folder and owner from `acme-platform/catalog.yaml`, required change ("route S3 traffic from the private subnets through an S3 gateway endpoint"), acceptance criteria (CI green; only `*.tf` in target folder changed; `PR_SUMMARY.md` written), constraints (no apply, no merge, no other folders, do not run commands).
2. **gitops**: shallow clone `DEMO_REPO` into `runs/<run_id>/work/`, branch `finops/<case-id>`.
3. **Executor** (pluggable):
   - `TemplateFixer`: writes a fixed `aws_vpc_endpoint` (Gateway, S3) block into the target `infra/` and a templated summary. Default in tests and fallback.
   - `DevinFixer`: runs `devin -p --prompt-file brief.md --permission-mode accept-edits --respect-workspace-trust false [--model $DEVIN_MODEL]` in the clone, timeout 10 min; reads `PR_SUMMARY.md`.
4. **Verify**: changed files ⊆ target folder and allowed patterns; non-empty diff; summary contains case ID and evidence IDs. Fail → do not push; show the reason; offer the template fallback.
5. **Publish**: commit, push branch, `gh pr create --repo $DEMO_REPO --base main --title … --body-file …`; store the PR URL; poll `gh pr checks` for CI status.
6. Reset script closes demo PRs and deletes `finops/*` branches (only in `DEMO_REPO`).

### 8.3 Demo monorepo `acme-platform` (public)

### Differences from the plan above
- Tools live in one module, `detective/tools.py` (not a `tools/` package); inbox actions in `detective/actions.py`.
- `get_utilization` takes several resource IDs at once (keeps the agent under ~6 calls per driver).
- **Planned** = approved ticket covering the date (linked by `change-id` tag, or cited and consistent with instance type and
  count) or an active exception. A matching budget is shown as context only: a shared budget alone would wrongly make the
  NAT charge "planned".
- Code finds exact resource-ID matches itself in the evidence pool; the agent's linking matters for non-exact leads (NAT).
- Cost start: first metric hour for instances, NAT bytes step-up for network; money is computed to the end of the spike day.
- Retry/escalation per driver: Haiku → Haiku with code's feedback → Sonnet → "needs human review". A rejected AI write-up
  falls back to a deterministic write-up (logged in the audit trail).
- Variant scenarios drop the load test and NAT scenes, so each Bedrock eval run is 6 driver investigations.
- Case IDs: `TUE-01..03`, `MIS-01`, `NCF-01`, `INJ-01`. In variant scenarios the GPU launch is `ct-003` (load-test event dropped).
